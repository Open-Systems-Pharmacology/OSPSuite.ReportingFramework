# Upgrade an esqlabsR Project to a ReportingFramework Project

Adds reporting-framework-specific configuration and template files to a
project directory. This is the second step in the two-step project
initialization workflow:

1.  Call
    [`esqlabsR::initProject()`](https://esqlabs.github.io/esqlabsR/reference/initProject.html)
    to set up the base esqlabsR project.

2.  Call `upgradeToReportingFramework()` to add RF-specific components.

## Usage

``` r
upgradeToReportingFramework(
  configurationDirectory = ".",
  templatePath = system.file("templates", package = "ospsuite.reportingframework"),
  analysisSubfolderName = "ReportingFramework",
  overwrite = FALSE,
  keepEsqlabsRStructure = TRUE
)
```

## Arguments

- configurationDirectory:

  A character string specifying the path to the RF configuration
  directory to be set up. Defaults to the current working directory.

- templatePath:

  Path to the RF template files. Defaults to the package templates.

- analysisSubfolderName:

  Name of the analysis subfolder used for initialization defaults. This
  value updates ReportingFramework-specific template defaults such as
  \`outputFolder\` when \`keepEsqlabsRStructure = FALSE\`. Defaults to
  \`"ReportingFramework"\`.

- overwrite:

  A logical value indicating whether to overwrite existing files.
  Defaults to `FALSE`. If an existing ReportingFramework project is
  detected in \`configurationDirectory\`, the upstream
  \`esqlabsR::initProject()\` step is skipped to avoid destructive
  reinitialization.

- keepEsqlabsRStructure:

  If \`TRUE\` (default), keep the existing esqlabsR directory/layout
  values and only add reporting-framework-specific components. If
  \`FALSE\`, apply reporting framework default configuration values and
  transfer files generated by esqlabsR initialization into the new
  structure.

## Value

Invisible NULL. Used for its side effects of creating directories and
copying files.
